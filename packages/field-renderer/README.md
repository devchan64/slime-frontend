# 공용 필드 렌더러

`@slime/field-renderer` 1.0.26은 게임과 관리도구 마을·필드 검수가 동일하게 실행하는 Phaser 3.90.0 렌더러다. `field-surface` 1.0.5의 고도·투영 계약을 사용한다. 타일·절벽·계단의 실제 그리기, 결계탑 앵커, 결계 외곽 판정·패널·UV·재생과 메시 경계 표시를 소유한다.

소비자는 준비된 Phaser Scene, 텍스처 키, 맵 표면, 투영 옵션, 깊이와 표시 옵션을 전달한다. 렌더러는 로그인·HTTP·파일 경로에 의존하지 않는다. 게임은 기존 뷰포트 캐시로 셀을 만들고 제거하며, 검수는 같은 함수를 호출하고 카메라·표시 옵션을 제어한다. 마을 건물과 연결점 표시는 `town-renderer`가 게임의 원본 구현을 재내보낸다. 전투 진행과 캐릭터 애니메이션 상태 관리는 소비자의 책임이다.

`drawFieldCellObjects`가 반환한 객체는 호출자가 폐기한다. 오러는 객체 폐기 시 프레임 이벤트를 해제한다. 연결 텍스처는 Scene의 텍스처 관리자에 캐시한다. 메시 좌표는 화면 좌표로 입력하며 Phaser의 위쪽 Y축 변환은 패키지가 담당한다. 결계는 바닥 음영 없이 외곽 엣지 전체에 높이 25px의 패널을 세운다.

배포는 `npm run build:field-renderer`로 수행한다. `.tmp/field-renderer/1.0.26/`의 ES 모듈·Phaser 배포본·SHA-256 manifest를 관리도구 `ui/map/vendor/field-renderer/`에 명시적으로 전달한다. 라이브러리 변경 시 버전을 올려 빌드하고 관리도구의 단일 배포본을 교체한다. 관리도구는 manifest의 버전으로 게시 URL을 생성한다. 과거 배포본은 Git 이력에 보존하며 field-surface는 번들 안에 포함한다. 관리도구 실행·게시 단계에서 인접 게임 소스를 빌드하지 않는다. 게임 전체 빌드도 필요 없다.

회귀 확인: `node scripts/run-regression.mjs --with-checks tests/field-renderer.test.mjs tests/field-surface.test.mjs tests/elevation.test.mjs`. 메시 검사는 Phaser 실제 Vertex·Matrix 투영으로 엣지 너비·높이·Y 방향을 확인한다.

1.0.6은 높은 평면의 단차 경계에 검은색에 가까운 짙은 회색(#303030) 4px 선을 추가합니다. 같은 높이의 평면 타일 사이·맵 바깥에는 선을 그리지 않습니다. 계단 접합부·각 디딤면·측벽의 네 모서리에는 같은 선을 적용하며, 각 면의 깊이 순서로 가림을 유지합니다. 선은 화면 CSS 픽셀 기준 4px로 고정하며 확대·축소와 내부 렌더 해상도를 보정합니다. 배율 변경 때만 다시 그리고 셀 캐시와 함께 폐기합니다.

도로는 연결 마스크의 둥근 외곽에 화면 4px 경계선을 적용합니다. 연결된 도로 타일 사이와 교차점 내부에는 선을 그리지 않습니다.

1.0.26의 `town-renderer.mjs`는 게임의 `createTerrainAtlas`, `drawCityBuildingSprite`과 깊이·크기 계약을 그대로 내보낸다. 이미지 import는 에셋 저장소의 논리 경로로 빌드하며 검수 클라이언트가 검증된 등록 원본을 연결한다. Phaser 엔진은 별도 모듈 한 개를 공유하고 번역 카탈로그는 빌드 시 포함한다.

렌더링 조정값의 단일 원본은 `render-constants.mjs`입니다. 게임의 `renderQuality`·`renderMetrics`와 지형·액터 코드는 여기서 가져오며, 기존 export는 호환 재내보내기입니다. 타입 선언은 값 없이 타입만 기술합니다. 상수를 바꾼 뒤 공용 번들을 새 버전으로 빌드하여 관리도구에 반영합니다.

소스 관리 주체는 `slime-frontend`이며 게임과 관리도구의 렌더링 규칙을 단일 원본으로 유지합니다. 관리도구 vendor는 편집 대상이 아닌 버전별 배포 산출물입니다. 소비 어댑터에 중복된 타일 선택·렌더링 규칙이 남아 있으면 관련 변경 시 공용 함수로 통합하고, UI·데이터 조회·카메라·선택·캡처만 소비자에서 관리합니다.

경비센터는 공용 `resolveGuardDisplayPlacement`로 도시 입구에 가장 가까운 도로 인접 평지 2×2를 선택한다. 도로·물·장애물·계단과 겹치지 않으며 네 셀의 투영 좌표 평균을 표시 중심으로 사용한다. 발급 접점은 기존 관문 좌표를 유지한다. 야외 도로는 원본 텍스처를 셀 전체에 배치하고 일반 재질 경계선을 공유한다.

지형·건물 텍스처 경로의 편집 원본은 `src/game/terrain/terrain.asset-list.yaml`이다. `scripts/asset-list-module.mjs`가 중복 키·자료형·허용 경로를 검사하고 정적 import로 변환한다. Vite 게임 빌드와 공용 렌더러 빌드가 같은 변환기를 사용한다. 배포 JS의 경로 변수는 자동 생성 결과이며 직접 편집하지 않는다. 등록 원본·버전·해시는 에셋 저장소 등록부와 `map-assets.lock.yaml`에서 검증한다.


## 필드 지형지물

맵 응답의 `objects`는 `id`, `kind`, `position: {column, row}`를 갖는다.
에셋 맵 원본의 `field_tiles/<map>.yaml`에서 등록하며 별도 통행 속성은 허용하지 않는다.
`ward-tower`는 공용 결계탑 접지·크기를 사용한다. `decoration`은 로딩된 `textureKey`,
`displayHeight`(화면 기준 높이), `anchorX`, `anchorY`(0–1 접지 비율)를 명시한다.
새 나무 스프라이트는 게임과 검수 양쪽의 에셋 로딩 목록에 먼저 등록해야 한다.
`drawFieldSceneryObject`에 고도·회전이 반영된 타일 중심과 해당 타일 깊이를 전달한다.
객체 생성은 충돌 셀을 추가하지 않으며 통행은 원래 타일·지형 계약을 따른다.


`tileAnchor`는 `back / center / front` 중 하나다.
기본값은 `center`이며 결계타워에도 동일하게 적용한다. 맵의 열·행을 함께 이동하는 3점 배치로,
뒤와 앞은 중심에서 각각 −0.25와 +0.25타일 떨어진 위치다. 화면 방향이 아닌 맵 방향에 고정되어 회전 시 함께 회전한다.
이미지의 접지 비율 `anchorX/Y`와 구분한다. `resolveFieldSceneryPlacement`는 소속 타일 중심의 고도를 유지하며
선택한 위치의 화면 좌표와 깊이 계산용 소수 좌표를 반환한다. 인접 타일 고도나 통행 속성을 조회·변경하지 않는다.

### 지형 이동 버전 2와 수풀 레이어

높이 한 단계는 20 월드 단위다. `terrainMovementVersion: 2`는 상·하행 모두 높이 차이 1까지 허용하며 경사로 레코드를 사용하지 않는다. 버전이 없는 기존 전투는 이전 이동 규칙을 유지한다.
`kind: billboard`는 가로로 나란한 뒤·앞 프레임을 같은 원점에 그린다. `frameSize`는 각 정사각 프레임 크기이며 캐릭터 깊이는 두 레이어 사이에 둔다. `groundOverrides`는 지정 셀의 바닥 텍스처만 바꾸며 이동 비용과 충돌은 바꾸지 않는다.


## 선택 맵 리소스 로딩

- `./resource-plan`의 `collectMapResourceKeys(map, kind)`는 `field`, `town`, `battle`을 구분한다. 지형 행 또는 전장 셀에 실제 사용된 재질, 배치 오브젝트·지면 덮어쓰기, 웨이포인트, 건물 재질을 수집한다. 전장 바위 변형은 게임과 같은 `resolveBattleTerrainResourceFrame`을 사용한다.
- `town-renderer` 배포 모듈의 `collectMapTextureSources()`는 게임의 지형·빌보드 등록 원본을 텍스처 키에 연결한다. 소비자는 선택 키만 카탈로그 URL로 해석한다. 카탈로그 목록 조회와 이미지 다운로드는 구분한다.
- `./resources`의 `loadMapResourceImages([{key,url}], {signal,onProgress})`는 동일 URL을 한 번만 요청하고 최대 6개를 병렬 로드한다. 키 충돌은 요청 전에 실패하며 하나의 실패 또는 취소는 같은 로딩의 나머지 요청을 중단한다. 실패 이미지를 대체하지 않는다. 완료 결과는 키별 이미지 객체다.
- 관리도구는 현재 선택한 맵의 이미지에만 이 로더를 사용한다. 페이지 종료 시 AbortController로 요청을 중단하고 Phaser 장면을 해제한다. 종류·맵 변경은 새 문서로 전환하므로 이전 장면이 늦게 갱신되지 않는다.
- 마을·전장 아틀라스는 `createTerrainAtlas(scene, selectedKeys)`로 선택 원본만 합성한다. 야외 검수는 지면 원본을 직접 그리므로 아틀라스를 만들지 않는다.
- 전투필드 검수는 `createGame`의 선택 리소스 인자로 같은 계획을 전달하며 선택 전장에 있는 액터만 준비한다. 기존 실게임 초기 실행의 전체 preload 경로는 호환 유지하며, 실게임의 서버 상태 기반 맵 전환 전체를 이번 변경으로 전환한 것은 아니다.
- 브라우저 다운로드 URL·해시 고정 배포 구조와 API·원본 에셋 소유권은 유지한다. 라이브러리 변경은 새 버전으로 빌드하여 관리도구에 전달한다.

1.0.67은 도시 건물을 등록 스프라이트로 표시합니다. 원본 맵의 `sprite` 앵커와 유효 폭을 사용하며 입구·점유 판정은 유지합니다. 선택 맵의 건물 텍스처만 요청합니다.

## 일반 주택과 시설 건물

도시 건물은 `kind: facility | residence`로 구분한다. 기존 시설은 `facilityId`를 유지하고,
일반 주택은 `facilityId: null`, `facilityKind: residence`를 받는다. 모든 건물의 점유 셀은
서버가 `blocked`에 포함하며 렌더링 이미지의 투명 영역으로 통행 판정을 추론하지 않는다.
일반 주택은 시설 선택·접근 메뉴와 문 앞 안내 표시를 제공하지 않는다. 시설 건물은 기존처럼
외부 `entrance` 좌표에서 메뉴를 이용하며 내부 이동은 허용하지 않는다.

### 고지대 교량 계약

야외 필드의 선택적 `bridges`는 지면 `elevations`를 바꾸지 않는 독립 상판이다.
각 항목은 `id`, `start: {column, row}`, `end: {column, row}`, `elevation`, `material`을 갖는다.
양끝은 육지 진입점이며 사이의 직선 셀이 교량이다. 상판 고도는 1~9,
재질은 `timber` 또는 `stone`이다. 진입점과 상판의 높이 차이는 1 이하,
상판은 모든 중간 지면보다 높아야 한다. 구간·진입점 중복과 대각선 교량은 거절한다.

원본 지형에서 교량 아래 셀은 `blocked`로 지정한다. 서버 응답·검수 표시에서
상판 셀만 이동 가능하게 노출하고, 양끝 진입과 다리 방향의 이동만 허용한다.
FP는 `road` 비용을 사용한다. 캐릭터·선택·길찾기는 상판 높이,
물·절벽 렌더링은 원래 지면 높이를 사용한다. 게임과 검수는 같은 렌더러를 쓴다.

현재는 한 칸 폭의 직선·단일 보행층이다. 다리 아래 동시 통행, 교량끼리 교차,
곡선·분기·다층 위치 저장은 지원하지 않는다. 교량이 없는 맵과 이전 전투 스냅샷의
계약은 유지하며 도시·전장에는 교량을 추가하지 않는다. 상판은 공용 형상으로
그리며 별도 이미지·GPU 생성 작업이나 배포 인프라 변경이 필요하지 않다.

### 독립 다층 이동 모듈 (1.0.107)

`buildLayeredTraversal(surface)`는 지면과 교량 상판을 별개 노드로 구성한다. 입력의 `blocked`는 원본 지면 차단 목록이며 `prepareBridgeTraversalSurface`로 상판 칸을 제거한 단층 스냅샷을 전달하지 않는다. 위치는 `{column,row,surfaceId}`이며 생략한 `surfaceId`는 `ground`, 상판은 교량 ID다. `ground`는 예약 ID다. 차단 위치에 교량 ID를 지정하면 상판만 차단된다.

반환 객체의 `listSurfacePositions`, `readSurfaceElevation`, `listSurfaceNeighbors`, `canTraverseStep`, `findSurfaceRoute`를 사용한다. 경로는 시작점을 제외하고 목적지를 포함하며 도달 불가는 `null`, 동일 위치는 빈 배열이다. 존재하지 않는 위치·층·잘못된 차단 데이터는 예외로 거절한다. 최단 경로는 이동 횟수 기준이며 기존 게임의 FP 최적 경로를 대체하지 않는다. 같은 좌표의 상하층은 서로 인접하지 않는다. 양끝 지면에서 상판으로 진입하며 통행 가능한 하부에는 고도 2 이상의 여유를 요구한다. 교차·중첩 교량은 기존 검증에 따라 거절한다.

`projectLayeredPosition(position, graph, options)`는 선택한 층의 높이로 투영한다. `pickLayeredPosition(point, surfaceId, graph, options)`는 명시한 층의 타일 상면을 선택한다. 별도 층 선택 UI용이며 전체 게임의 절벽·오브젝트 가림 판정을 대체하지 않는다. 백엔드의 동일 계약은 `app.layered_traversal.LayeredTraversalGraph`다. 그래프는 입력 시점의 독립 스냅샷이며 맵이 바뀌면 다시 구성한다.

현재 적용 범위는 독립 이동 엔진과 공용 투영이다. 게임 HTTP 위치·저장·FP·몬스터·조우는 기존 단층 계약을 유지하며 새벽 전망대에 다층을 적용하지 않는다. 실제 게임 맵 활성화 시에는 해당 계약과 층 선택·가림 처리를 함께 연결해야 한다. 인프라·배포 구조·운영 비용 변경은 없다.

격리 검증 원본은 `tests/fixtures/layered-movement-review.{html,mjs}`다. mjs를 esbuild로 bundle.js로 묶고 HTML을 index.html로 복사하여 기존 8770 서버의 독립 정적 검증 경로에서 확인한다. 노랑을 동쪽 두 칸, 파랑을 남쪽 한 칸 이동하면 `(3,3)`의 상판과 지면을 동시에 확인할 수 있다. PNG 출력은 화면 버튼을 사용한다.

### 교량 분할 스프라이트 (1.0.108)

목교·석교는 `assets/buildings/bridge-{timber,stone}-components-v1.png` RGBA 원본의 상판·측면 보·난간·교대 영역을 UV로 나누어 투영한다. `bridge-geometry.mjs`가 재질별 원본 영역과 두께를 관리하며 별도 이미지 크롭 사본을 만들지 않는다. 석교 측면 아치는 교량 길이 전체에 연속 UV로 연결한다. 앞 난간은 캐릭터 앞, 뒤 난간은 캐릭터 뒤의 깊이를 사용한다. 교량 선택 리소스 계획과 게임의 지형지물 로더가 같은 등록 원본을 사용한다. 누락된 교량 이미지는 명확한 오류로 처리한다. 기존 상판 높이·통행·비용·수면 데이터는 유지한다.

### 교량 연결부·보강 부재 (1.0.109)

진입 타일은 육지 쪽으로 넓어지는 상판과 지면 높이를 따르는 경사면, 양측 진입 난간, 전면 교대·날개벽으로 연결한다. 경계에는 작은 겹침을 두어 틈을 막는다. 목교는 주보 두께·하부 면·횡보·양끝 사재를 추가하고, 석교는 기존 연속 아치의 개구부를 보존하면서 상부 돌림띠를 추가한다. 하천 중앙 교각은 추가하지 않는다. 기존 이동 판정·상판 고도·맵 데이터는 유지하며 등록된 텍스처를 재사용한다. 이는 시각 부재 구성으로 구조 안전 계산을 제공하지 않는다.

양안 받침기둥은 인접한 교량 하부 지형 높이까지 내려 바닥에 묻히게 한다. 난간 진입 끝에는 원본 기둥 UV를 사용한 고정 기둥을 추가한다. 강 중앙의 교각과 이동 장애물은 추가하지 않는다.

### 연결부 확대 검수 수정 (1.0.110)

교대·받침기둥 상단은 주보 하단보다 낮춰 상판과 겹쳐 보이지 않게 한다. 진입 상판과 본체는 정확히 같은 경계·높이에서 맞물리며 육지 쪽에 낮은 문턱을 둔다. 진입 난간은 기둥 양끝을 포함한 전체 UV를 사용하고 중복 추가 기둥을 제거한다. 기존 이동·지형 데이터는 유지한다.

### 연결 부재별 재질 (1.0.111)

`bridge-connection-details-v1.png`에 진입 포장·모서리 석축·받침돌 상면·목재 접합 철물 4개 영역을 추가한다. 진입 포장의 흙 가장자리는 육지 방향으로 정렬한다. 교대·날개벽·기초는 석축, 기둥 윗면은 받침돌, 목교 사재는 접합 철물 영역을 사용한다. 교량이 있는 맵에만 공통 연결부 아틀라스 한 장을 추가 로드한다.

### 석교 접합·아치 내부 (1.0.112)

석교의 교대와 날개벽은 상판 바로 아래까지 채우고 받침돌만 아치 시작 높이에 둔다. 목교의 보 아래 받침은 유지한다. 등록 석교 아치의 투명 경계에 맞춘 분할 곡면으로 안쪽 면을 연결한다. 석교 난간의 타일 접합에서는 양쪽 끝 기둥을 절반씩 남겨 이중 폭을 줄인다. 지형·이동 계약과 에셋 원본은 바꾸지 않는다.

### 아치 경간 단위 합성 (1.0.113)

석교의 측면 아치는 전체 경간을 한 패널로 그려 타일별 UV 절단을 제거한다. 측면·내부 곡면은 같은 구조 깊이 기준점을 사용하며 뒤 아치→내부→앞 아치 순서로 합성한다. 내부 석축 UV도 경간 전체에서 연속시킨다. 상판·난간·캐릭터와 지형 이동 계약은 유지한다.

석교 내부 셀의 상판·난간·캐릭터는 경간과 같은 기준 깊이를 사용하여 연속 아치가 보행면을 덮지 않게 한다(1.0.114). 목교의 기존 셀별 깊이는 유지한다.

### 아치 하상 접지 (1.0.115)

석교 측면과 내부 곡면의 깊이는 양안 하상 높이와 기초 매입 깊이를 기준으로 계산한다. 양쪽 하상 높이가 다르면 경간을 따라 보간하며 아치 끝과 받침을 같은 기초 높이에 연결한다.

### 석교 보강 정리 (1.0.116)

하상까지 닿는 석교 아치에는 별도 돌출 받침기둥을 중복 배치하지 않는다. 육지 쪽 날개벽 길이는 0.75칸에서 0.25칸으로 줄이고 교대 전면과 기초 깊이는 유지한다. 목교 보강과 통행면은 유지한다.

### 목교 보강 정리 (1.0.117)

목교도 별도 돌출 받침기둥을 제거하고 날개벽 길이를 0.25칸으로 통일한다. 교대 전면·기초 깊이와 목재 주보·횡보·사재, 통행면은 유지한다.

### 석교 진입 타일 합성 (1.0.118)

진입 타일의 교량 부재도 본체와 같은 깊이 기준점을 사용한다. 교대·상판·난간의 부재별 순서를 유지하여 접합부에서 아치가 진입 난간을 덮는 문제를 막는다. 지형 타일의 깊이는 바꾸지 않는다.

### 석교 하단 매립면 제거 (1.0.120)

육지 타일 안에 묻힌 석교 날개벽은 생성하지 않고, 지면 위로 노출된 높이만 남긴다. 교대 전면과 아치의 하상 접지는 유지하여 하단 지형 측면에 돌판이 겹치는 현상을 방지한다.

### 교량 접합 공통 규칙 (1.0.122)

교대의 뒷면 제외와 지면 아래 날개벽 제거를 재질 공통으로 적용한다. 목교·석교 난간은 내부 접합 기둥의 절반씩을 사용하고 목교 횡보는 각 경계의 한 셀만 생성한다. 통행면과 이동 계약은 유지한다.

### 공통 아치 교량 구조 (1.0.123)

목교와 석교는 전체 경간 아치·내부 곡면·하상 접지·교대 노출 판정·상판·난간·깊이 정렬을 같은 구현으로 사용한다. 재질 프로필은 스프라이트와 UV를 선택하며 목교는 목재 아치 v2와 목재 내부 면을 사용한다. 이전 직선보·사재 전용 분기는 제거한다.

### 아치 스프라이트 접지 여백 제거 (1.0.124)

목교·석교 아치 UV의 좌우 투명 여백과 하단 여백을 제외한다. 내부 곡면의 개구부 비율도 같은 UV 변환에 맞춰 보정하여 기초 좌표와 실제 아치 그림이 일치하게 한다. 원본 이미지와 이동 고도는 유지한다.

### 1.0.125 측벽 텍스처 비율

측벽 무늬의 반복 높이는 투영면의 수평 폭 × 원본 이미지 높이/너비로 계산한다. 고도 한 단계(10px)마다 이미지 전체를 압축하던 방식을 제거하고, 낮은 측벽과 마지막 반복 구간은 UV 일부만 사용한다. 기본 80px 타일의 정사각형 원본은 40px 높이마다 반복하며 지형 고도·충돌·깊이 판정은 유지한다.

### 맵 종류별 렌더 배율

`resolveMapRenderOptions({renderKind: 'field' | 'town' | 'battle'})`로 지면과 빌보드의 렌더 옵션을 함께 선택한다. 야외필드는 80×40·`billboardScale: 0.5`, 마을과 전투필드는 160×80·배율 1이다. 고도·앵커·논리 점유 영역과 원본 `displayHeight`는 바꾸지 않는다. `drawFieldSceneryObject`의 여섯 번째 인자로 옵션을 전달하면 일반 장식과 앞뒤 2프레임 빌보드에 동일하게 적용된다. 결계탑과 캐릭터는 이 빌보드 배율의 대상이 아니다.

빌보드 깊이는 `resolveFieldSceneryDepth`로 계산한다. 소속 타일의 회전된 지면 좌표로 먼저 정렬하고, 상단·하단 앵커는 같은 타일의 캐릭터 앞뒤 레이어만 선택한다. 화면 배치를 위한 ±0.5타일 이동을 깊이에 다시 적용하지 않는다. 명시적 상하 앵커의 2프레임도 선택한 레이어 안에서 함께 그린다. 캐릭터·지형 레이어 간격은 유지하며 배치 배열 순서에 의존하지 않는다.

빌보드 접지 그림자는 기본 활성화이며 `billboardShadows: false`로 비활성화한다. 공용 렌더 배율·타일 앵커·회전을 반영한 3겹 타원 그림자를 지면 바로 위에 그린다. 투사광이나 다른 물체에 드리우는 실루엣 그림자는 포함하지 않는다. 이미지가 파괴되면 그림자도 해제한다.

열·행 점유 수가 다른 빌보드는 점유 축을 따라 둥근 직사각형을 지면에 투영한다. 폭·길이는 선언된 점유 수의 55%, 모서리 반경은 짧은 반축의 35%다. 동일한 3겹 농도와 회전·배율을 적용하며 정사각 점유는 기존 타원을 유지한다.

그림자 중심은 소속 타일 중앙이다. 빌보드의 상단·하단 앵커 이동을 역투영해 제거하며, 긴 점유 영역도 같은 중앙을 기준으로 회전한다.
